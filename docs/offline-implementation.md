# Provisional offline implementation boundary

The desktop lock does not justify a new execution platform. Explicit
authorization permits N01-N07 source implementation and offline N08-N09
checks while N00/native N08 remain blocked.

## Implemented mechanisms

The authoring contract validates source identity/order/hash references,
observed/documented/inferred support, confidence separately, user answers tied
to blueprint revision/bytes, actual implementation bindings, bounded repeats,
dependency DAGs, defaults/constants, current candidate/evaluation hashes and
native capability/setup gaps. It cannot prove that text was correctly
understood or that a user actually approved something.

The source assembler writes a new candidate directory only after its emitted
subset checks succeed. The packager preserves included source/tool bytes,
generates only its documented manifest properties/icons, checks same-skill
dependencies and resource budgets, and writes deterministic rooted ZIPs.
Canonical metadata remains mandatory; legal adequacy and native acceptance
cannot be established by local syntax checks.

Creation-source checkpoints include exact authoring/candidate files and a
complete hash inventory, not raw recordings/screenshots or secrets. They can
preserve a syntactically broken candidate as an explicitly diagnosed Draft.
Resume verifies every entry, creates a new directory, preserves old control
records under content-addressed history, and resets host/evaluation readiness.
Recorded evidence is not represented as a currently accessible attachment.

Correction merge compares a checkpoint base, current user project and a
proposed next revision. Separate changes are retained, same-file divergent
changes produce explicit conflicts and no output, and original trees remain
unchanged. This is not an atomic cross-session execution lock or permission
authority.

## Offline exercises

Three distinct positive families execute actual generated helpers:
exact filtered costs, priority-grouped checklists, and signed nonzero variance
ledgers. The latter includes a small negative difference to catch incorrect
signed-money formatting. All use bounded JSON input and new-file outputs.

Adversarial variants check unresolved/conflicting evidence, missing native
runtime/connection, unsupported desktop operations, unknown sample-value
classification, stale evidence/evaluations, missing passing cases, forbidden
imports and unresolved source tokens. Unit tests additionally cover exact
limits, conservative user-edit merge, tampered/traversing source bundles,
preserved publisher gates and real public MCP metadata semantics.

These are deterministic tests and controlled synthetic fixtures, not model
activation benchmarks or native end-to-end evaluations. The prompt corpus
provides additional future walkthroughs with outcomes left unverified.

## Remaining gates

The original output publication result is unknown after a single click and
desktop lock. Do not replay it without checking native state. No independent
native invocation, direct canonical v1.28 acceptance, real Cowork Learn
connection, broad video/narration validation or native schedule is established.

The expanded candidate needs its own native installation and resource/CLI
exercise, rather than inheriting evidence from v0.1.0. Each output needs
independent new-input invocation. Real workflows need real native connections,
user-provided publishing metadata when required, actual process clarification
and platform approvals.
